# Research: YouTube transcript + metadata access (.NET vs Python)

Date: 2026-09-30. Scope: getting a video's transcript (manual + auto captions, any language), title, description, chapters and thumbnail from a `youtube.com/watch`, `youtu.be` or `/shorts/` URL, for Video Import. Compares YoutubeExplode (.NET), youtube-transcript-api and yt-dlp (Python), and the official YouTube Data API v3. Standing decision: stay .NET unless it clearly falls short.

Legend: **[doc]** = stated in the primary source linked. **[src]** = read in upstream source code. **[measured]** = run locally for this note (macOS arm64, residential IP, 2026-09-30; YoutubeExplode 6.6.2 on .NET 10.0.401, youtube-transcript-api 1.2.4 on Python 3.14.7, yt-dlp 2026.08.19 with deno). **[inference]** = my conclusion.

---

## 1. Summary

- **Recommendation: .NET-only, YoutubeExplode 6.6.2.** It covered every field we need except chapters, and it did so on all test videos [measured]. Chapters can be parsed from the description in a few lines of our own code (§2.4). A Python sidecar doesn't beat it on the main risk: all three libraries use the same unofficial InnerTube endpoints and all get blocked in the same situations.
- **The official Data API can't be used for transcripts.** `captions.download` requires OAuth and "permission to edit the video", so it only works for your own videos (§5). It's fine for metadata but not needed, since YoutubeExplode returns the same metadata.
- **Main risk (same for every option):** YouTube changes things. PO-token rollout, client deprecations, cloud-IP blocking. Expect a NuGet bump every few months and occasional breakage between them. Running locally on a home IP is the best case. A later cloud deployment will probably hit IP blocks (§6).

## 2. YoutubeExplode (.NET)

Repo https://github.com/Tyrrrz/YoutubeExplode, NuGet `YoutubeExplode`.

### Facts

- **Licence:** MIT [doc]. The README also has a "Terms of use" section: users must "condemn Russia and its military aggression against Ukraine" [doc, README]. This is the maintainer's stated condition, not an OSI licence clause. It's fine for a personal project, but worth knowing about.
- **Activity:** 3.7k stars, not archived, last push 2026-09-01 [doc, GitHub API]. Releases: 6.6.2 (2026-08-25), 6.6.1 (2026-08-07), 6.6 (2026-04-22), 6.5.7 (2026-02-12), 6.5.6 (2025-10-25), 6.5.5 (2025-10-04) [doc]. Most recent fixes are reactions to YouTube changes: 6.5.6 "Change the client to avoid the 403 error", 6.5.7 "Switch to ANDROID_VR client to bypass YouTube PO token requirement", 6.6.2 "Fix download errors by using mostly VISIONOS agent" [doc, release notes].
- **Targets:** `netstandard2.0;net6.0;net7.0;net10.0`. Pure managed code, with no native or JS runtime needed for metadata or captions [src, `YoutubeExplode.csproj`]. Muxing and conversion need FFmpeg, but we don't use them.
- **Mechanism:** unofficial. It POSTs to `https://www.youtube.com/youtubei/v1/player` pretending to be the `VISIONOS`, `ANDROID` or `TVHTML5_SIMPLY_EMBEDDED_PLAYER` client [src, `Videos/VideoController.cs`]. Caption tracks come from the player response's `captionTracks` URLs, forced to `format=3` (srv3 XML) [src, `ClosedCaptionController.cs`].
- **API used:**
  - `VideoId.Parse(url)` accepts watch, youtu.be and shorts URLs [measured].
  - `Videos.GetAsync(id)` returns `Title`, `Author`, `UploadDate`, `Description`, `Duration`, `Thumbnails`, `Keywords` and `Engagement`. **There's no chapters property** [src, `Videos/Video.cs`].
  - `Videos.ClosedCaptions.GetManifestAsync(id)` returns `Tracks`, each with a `Language.Code` and `IsAutoGenerated`. `GetAsync(trackInfo)` returns `Captions`, each with `Text`, `Offset` and `Duration` [measured].
  - It doesn't support YouTube's machine translation of tracks (`tlang`). We don't need it, because the LLM writes German anyway [inference].
- **HttpClient seam:** `new YoutubeClient(HttpClient)` exists, so tests can inject a handler and IHttpClientFactory can be used [src, `YoutubeClient.cs`].
- **Open breakage reports (2026):**
  - #964 (2026-08-07, v6.6.1) "Closed caption tracks are not retrieved". A contributor says the 6.6.2 PR fixes it. It's still open, and the maintainer asked (2026-09-20) whether the reporter was authenticated. **With 6.6.2, `k68rAwize_Y` from that issue returned its track [measured].**
  - #969 (2026-09-11) "GetPlayerResponseForVisionOsAsync fails with 400 Bad Request on all videos". Reported from a YoutubeDownloader CI build, logged in with cookies. **Not reproduced here with anonymous use [measured].**
  - #967 is UWP .NET Native only, so it doesn't affect us.
- **Rate limits:** there's no built-in retry or backoff [inference from src]. YouTube doesn't publish limits for these endpoints. Our existing retry policy in the backend would apply.

### Measured (2026-09-30)

| Video | Kind | Result |
|---|---|---|
| `i84Sc5uvQa8` (watch URL) | EN recipe, auto captions | title, 1995-char description, maxres thumbnail, `en(auto)` with 358 captions |
| `6wR2T-PexT4` (youtu.be URL) | DE, 36 min | `de(auto)` with 1666 captions. The ASR opens with a few Russian-hallucinated lines (the same in every library) |
| `dQw4w9WgXcQ` | manual tracks | `en, en(auto), de-DE, ja, pt-BR, es-419`: manual and auto are told apart correctly |
| `MGKYhCRwrN0` (`/shorts/` URL) | no captions | metadata OK, `Tracks` empty, **no exception**. This maps to our "no captions → failure" rule |
| `k68rAwize_Y` | issue #964 repro | `en(auto)`, 1198 captions |

Thumbnails: the best URL is `maxresdefault.jpg`, or `.webp` for some videos [measured]. The image pipeline has to accept WebP, or we can request the `/vi/<id>/maxresdefault.jpg` form (hqdefault as fallback) [inference].

### 2.4 Chapters without library support

- YouTube builds creator chapters from timestamps in the description (`0:00 Intro` …, the first at 00:00) [doc, Data API `videos` resource: "You can create video chapters by including formatted timestamps"]. Both multi-recipe test videos had them (`6tMZNYQkycI`: 10 recipes, `6wR2T-PexT4`: "Rezept 1..5") [measured].
- Auto-generated chapters ("key moments", e.g. the Short's `<Untitled Chapter 1>`, "170 GM CREAM…") only appear in the player/engagement data. yt-dlp returns them. YoutubeExplode doesn't [measured].
- **[inference]** Since the description already goes to the LLM in full, parsing chapters is optional. A small regex (`^(\d{1,2}:)?\d{1,2}:\d{2}\s+(.+)$`) in our own module gives structured chapters for splitting one video into N recipes. Losing auto chapters is minor.

## 3. youtube-transcript-api (Python)

Repo https://github.com/jdepoix/youtube-transcript-api.

- **Licence:** MIT. 8.4k stars, last push 2026-09-10 [doc]. Releases: **v1.2.4 (2026-01-29)**, v1.2.3 (2025-10-13, "support for python 3.14"), v1.2.2 (2025-08-04) [doc]. **There has been no release in 8 months**, and v1.2.4 was only a proxy/README fix [doc, release notes].
- **Scope:** transcripts only. There's no title, description or thumbnail, and "typed Metadata dataclass" is an open feature request (#605, 2026-06-10) [doc]. **For our metadata we'd still need something else** (yt-dlp or YoutubeExplode).
- **Mechanism:** scrapes `INNERTUBE_API_KEY` from the watch page, then POSTs to `youtubei/v1/player` with `clientName: ANDROID, clientVersion 20.10.38`. It raises `PoTokenRequired` if the caption URL contains `&exp=xpe` [src, `_settings.py`, `_transcripts.py`]. This is the same approach as YoutubeExplode.
- **Features:** list tracks as manual/generated, pick by language priority, `translate()`, clear exceptions (`TranscriptsDisabled`, `RequestBlocked`, `IpBlocked`, `PoTokenRequired`) [doc, measured].
- **Blocking:** the README says "YouTube has started blocking most IPs that are known to belong to cloud providers … you will most likely run into `RequestBlocked` or `IpBlocked`". The fix it recommends is rotating residential proxies (a Webshare referral) [doc, README]. Recent issues: #592 PoTokenRequired with no workaround (open, 2026-04-25; one commenter says `exp=xpe` means the video is in YouTube's PO-token rollout); #612 429 retries never rotate the IP (open); #606/#613 IP blocks (2026-06/07); #618 regional issues through a proxy (2026-09-28) [doc].
- **Measured:** same results as YoutubeExplode on all four videos (`TranscriptsDisabled` for the Short). Auto captions come back as 180 merged snippets vs YoutubeExplode's 358, which is just segmentation [measured].

## 4. yt-dlp (Python CLI/library)

Repo https://github.com/yt-dlp/yt-dlp.

- **Licence:** Unlicense. The PyInstaller binaries bundle other licences [doc, release page]. 194k stars, 2.6k open issues. Releases are frequent: 2026.08.19, 07.04, 06.09, 03.17, 03.13, 03.03 [doc].
- **Scope:** everything in one call. `%(title)s`, `description`, `chapters` (creator chapters *and* auto chapters), `thumbnail`, `duration`, `--list-subs` shows manual subtitles vs "automatic captions" plus `*-orig` tracks, in `json3/srv3/vtt/…` formats [measured].
- **Mechanism:** the same unofficial player API, over several clients (`visionos`, `tv downgraded`, `web embedded`…) [measured, log output]. The 2026.08.19 notes: "Add `visionos` player client", "Remove `android_vr` from default clients", "Player client maintenance" [doc]. It has the most maintainers and the fastest fixes when YouTube changes something [inference from release cadence].
- **Needs a JS runtime:** since 2025.11.12, "External JavaScript runtime now required for full YouTube support", with Deno recommended and Node 20+ supported [doc, issue #15012]. The log shows `[jsc:deno] Solving JS challenges using deno` [measured]. **In Docker that means Python + yt-dlp + Deno in the image.**
- **Cost for us:** a sidecar container (or a Python + Deno install in the backend image, calling the CLI as a subprocess), an extra language in CI, and parsing output JSON.

## 5. YouTube Data API v3 (official)

- `captions.list`: OAuth scope `youtube.force-ssl` or `youtubepartner`, **50 units** per call [doc https://developers.google.com/youtube/v3/docs/captions/list]. It returns track metadata only, no text [doc].
- `captions.download`: the same OAuth scopes, **"requires the user to have permission to edit the video"**, 200 units, 403 if permissions are insufficient [doc https://developers.google.com/youtube/v3/docs/captions/download, updated 2026-09-15]. **So it can't fetch transcripts of other people's videos. Ruled out.**
- `videos.list` (API key is enough): `snippet.title`, `snippet.description` (up to 5000 bytes), `snippet.thumbnails` including `maxres` 1280×720, and `contentDetails.caption` as a "captions available" boolean. There's no chapters field; chapters come from description timestamps [doc https://developers.google.com/youtube/v3/docs/videos]. It costs **1 unit**, with a default quota of **10,000 units/day** [doc https://developers.google.com/youtube/v3/determine_quota_cost].
- **[inference]** It would be a stable fallback for metadata only, but it needs a Google Cloud project and an API key, and it doesn't solve the transcript problem. Not worth it in V1.

## 6. Comparison

| | YoutubeExplode | youtube-transcript-api | yt-dlp | Data API v3 |
|---|---|---|---|---|
| Transcript (manual + auto, any lang) | yes | yes (+ translate) | yes | own videos only |
| Title / description / thumbnail | yes | **no** | yes | yes |
| Chapters | no (parse description) | no | yes (+ auto) | no (parse description) |
| No captions | empty `Tracks` | `TranscriptsDisabled` | "has no subtitles" | `caption=false` |
| Mechanism | InnerTube (unofficial) | InnerTube (unofficial) | InnerTube + JS challenge solving | official |
| Latest release | 6.6.2, 2026-08-25 | 1.2.4, 2026-01-29 | 2026.08.19 | n/a |
| Licence | MIT (+ political ToU) | MIT | Unlicense | Google ToS |
| Docker needs | nothing extra | Python | Python + Deno | API key |
| Fits .NET backend | in-process | sidecar | sidecar / subprocess | HttpClient |

**Blocking applies to all the unofficial options** [inference, backed by §2–4 issue reports]. Home and residential IPs work (measured, all three). Cloud and datacenter IPs are widely blocked (youtube-transcript-api README). PO-token rollout is making caption URLs return empty responses for some videos (#592). None of the three can mint PO tokens without a browser. yt-dlp has a PO-token provider plugin ecosystem, but it's outside our scope [inference]. For RecipeJoe running locally in docker compose, the container's traffic leaves from the Mac's home IP, so the local case matches what was measured [inference]. Deployment is out of scope, but the risk should be flagged in the spec.

**Where yt-dlp is clearly better:** auto chapters, and faster fixes when YouTube breaks things. **Neither clearly outweighs the cost of a second runtime** under the standing decision [inference]. Keep a seam so we can swap to a yt-dlp sidecar later if YoutubeExplode stays broken.

## 7. Design + test implications

- **Seam:** a `VideoTextSource`-style module with one method (URL → `{ title, description, chapters[], transcript { language, isAutoGenerated, text }, thumbnailUrl }`, or a typed failure: `NotYouTube`, `Unavailable`, `NoCaptions`, `Blocked`). YoutubeExplode stays hidden behind it. A yt-dlp adapter could come later [inference, codebase-design].
- **Track choice (suggested):** manual over auto. Within each, prefer the original language: the video's default track, i.e. the first auto track, which is the ASR of the spoken language. The LLM translates, so "any language" is fine [inference].
- **Test fixtures:**
  - *Unit/API/E2E:* a fake `VideoTextSource` returning canned domain objects (success, NoCaptions, Blocked, Unavailable). Don't record YouTube's internal HTTP (watch HTML, player JSON). Those payloads change with every client bump and would lock tests to YoutubeExplode internals [inference].
  - *Domain fixtures worth recording once* (as JSON of our own shape, from real runs): `i84Sc5uvQa8` (EN, single recipe, ingredients in description), `6tMZNYQkycI` (10 recipes with description chapters, for the 1→N split), `6wR2T-PexT4` (DE, long, noisy ASR with hallucinated Russian), `MGKYhCRwrN0` (Short, no captions → failure), `dQw4w9WgXcQ` (manual + auto tracks, for track choice). These also work as the LLM golden corpus inputs.
  - *Parser unit tests:* description → chapters (`0:00`, `0:00:00`, leading whitespace, the first timestamp must be 0:00).
  - *Optional live smoke test* (`just`-invoked, never in CI): one real fetch to spot YouTube breakage early. CI runners are cloud IPs, so they'd likely be blocked anyway [inference from README].

## 8. Unresolved questions

1. Accept the PO-token and cloud-IP risk for V1 and state it in the spec? Suggested: yes, local-only.
2. Chapters: parse the description ourselves, or just pass the raw description to the LLM? Suggested: parse (cheap, and helps with 1→N).
3. Thumbnail: accept WebP in the image pipeline, or always request the `.jpg` URL variant?
4. When a video has only an auto-translated track (no `*-orig`), is that still "captions available"? Suggested: yes, take whatever the manifest lists.
